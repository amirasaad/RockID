## Decision Policy

### Fix In-Wave
Criteria for fixing high-priority issues during Wave 1:
- Crash or data loss
- Complete blocker to core functionality (capture/upload/analyze)
- Security vulnerability
- Critical UX friction preventing mission completion

### Defer with Reason
Criteria for deferring high-priority issues:
- Issue is reproducible but low-frequency edge case
- Workaround exists that is acceptable for beta
- Issue requires significant architectural change (defer to Sprint 37)
- Issue is out of scope for Wave 1 (offline-only, GitHub-only feedback)
